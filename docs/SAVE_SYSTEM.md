# PROJECT STAR — SAVE SYSTEM

## 1. 저장 시스템 개요

저장 시스템은 플레이어의 현재 육성 진행 상황과 수집 기록을 보관하는 기능이다.

플레이어가 게임을 종료한 뒤에도 이전 진행 상태를 불러와 계속 플레이할 수 있어야 한다.

저장 데이터는 크게 두 종류로 나눈다.

- 현재 플레이 진행 데이터
- 영구 수집 및 기록 데이터

---

## 2. 현재 프로토타입 적용 범위

현재 3일 프로토타입에서는 기본 게임 흐름을 먼저 완성한다.

초기 구현 목표는 다음과 같다.

- 자동 저장
- 이어하기
- 새 게임 시작
- 최종 플레이 기록 저장
- 엔딩 도감 저장

여러 개의 수동 저장 슬롯과 클라우드 저장은 이후에 추가한다.

---

## 3. 저장 방식

### 자동 저장

게임의 중요한 진행 지점에서 자동으로 저장한다.

플레이어가 별도의 저장 버튼을 누르지 않아도 현재 진행 상태가 보관된다.

### 수동 저장

정식 버전에서 플레이어가 원하는 시점에 직접 저장할 수 있도록 추가한다.

초기 프로토타입에서는 수동 저장을 구현하지 않아도 된다.

### 영구 기록 저장

게임을 새로 시작해도 유지되어야 하는 데이터를 별도로 저장한다.

예시:

- 획득한 엔딩
- 확인한 이벤트
- 최고 순위
- 최고 팬 수
- 캐릭터별 플레이 횟수
- 도감 해금 상태

---

## 4. 자동 저장 시점

다음 상황에서 자동 저장을 실행한다.

- 연습생 선택 완료
- 행동 결과 적용 완료
- STAR EVENT 결과 적용 완료
- 하루 종료
- 다음 날 시작
- 최종 순위 결정
- 엔딩 확인
- 설정 변경

행동을 선택하기 전이 아니라 결과가 모두 적용된 뒤 저장한다.

---

## 5. 이어하기

타이틀 화면에 저장된 진행 데이터가 있으면 `이어하기` 버튼을 표시한다.

이어하기를 선택하면 마지막 자동 저장 지점에서 게임을 계속한다.

### 표시 정보

- 선택한 연습생
- 현재 날짜
- 남은 행동 횟수
- 현재 순위
- 저장한 날짜와 시간

저장 데이터가 없으면 이어하기 버튼을 비활성화한다.

---

## 6. 새 게임 시작

저장된 진행 데이터가 있는 상태에서 새 게임을 선택하면 확인 창을 표시한다.

### 확인 문구

> 진행 중인 플레이가 있습니다.  
> 새 게임을 시작하면 현재 진행 데이터가 삭제됩니다.

### 선택지

- 새 게임 시작
- 취소
- 이어하기

새 게임을 시작해도 도감과 엔딩 기록은 삭제하지 않는다.

---

## 7. 저장해야 하는 기본 정보

### 게임 진행 정보

- 현재 화면
- 현재 날짜
- 남은 행동 횟수
- 선택한 연습생
- 마지막으로 실행한 행동
- 게임 시작 시간
- 마지막 저장 시간

### 선택한 연습생 정보

- 캐릭터 ID
- 현재 체력
- 보컬 레벨과 경험치
- 댄스 레벨과 경험치
- 랩 레벨과 경험치
- 예능 레벨과 경험치
- 연기 레벨과 경험치
- 팬 수
- 스타성

### 경쟁자 정보

선택하지 않은 네 명의 연습생도 함께 저장한다.

각 경쟁자에게 다음 정보가 필요하다.

- 캐릭터 ID
- 능력치 레벨과 경험치
- 팬 수
- 스타성
- 현재 성장 점수
- 현재 순위

### 하루 기록

- 오늘 실행한 행동 목록
- 오늘 사용한 행동 횟수
- 오늘 증가한 팬 수
- 오늘 감소한 팬 수
- 오늘 획득한 스타성
- 오늘 발생한 이벤트
- 전날 순위
- 현재 순위

---

## 8. 이벤트 저장 정보

이벤트 진행 도중 게임을 종료해도 결과가 중복 적용되지 않아야 한다.

저장해야 하는 이벤트 정보는 다음과 같다.

- 현재 이벤트 ID
- 이벤트 발생 여부
- 선택한 선택지
- 결과 적용 여부
- 이미 확인한 이벤트 목록
- 이벤트별 확인한 결과
- 히든 이벤트 조건

결과가 적용된 이벤트는 다시 보상을 지급하지 않는다.

---

## 9. 미션 저장 정보

미션 시스템을 구현한 뒤에는 다음 데이터를 저장한다.

- 현재 메인 미션
- 현재 일일 미션
- 캐릭터 전용 미션
- 미션별 진행도
- 성공한 미션
- 실패한 미션
- 지급 완료한 보상
- 발견한 히든 미션

이미 받은 미션 보상은 불러오기 후 다시 지급되지 않아야 한다.

---

## 10. 아이템 저장 정보

아이템 시스템을 구현한 뒤에는 다음 데이터를 저장한다.

- 보유 아이템 ID
- 아이템별 수량
- 오늘 사용한 아이템 수
- 장착 중인 의상
- 사용 대기 중인 훈련 효과
- 획득한 캐릭터 전용 아이템

아이템 사용 직후 수량과 효과를 함께 저장한다.

---

## 11. 영구 기록 데이터

현재 플레이를 새로 시작해도 다음 데이터는 유지한다.

### 캐릭터 기록

- 캐릭터별 플레이 횟수
- 캐릭터별 최고 순위
- 캐릭터별 최고 팬 수
- 캐릭터별 최고 스타성
- 캐릭터별 최고 능력치
- 캐릭터별 확인한 엔딩

### 엔딩 도감

- 엔딩 ID
- 획득한 캐릭터
- 최초 획득 날짜
- 획득 횟수
- 엔딩 이미지 해금 여부
- 마지막 대사 해금 여부

### 이벤트 도감

- 확인한 이벤트
- 확인한 선택지
- 확인한 결과
- 아직 보지 못한 결과
- 이벤트 완전 수집 여부

### 전체 기록

- 전체 플레이 횟수
- 전체 데뷔 성공 횟수
- 최종 1위 달성 횟수
- 가장 많이 선택한 연습생
- 최고 팬 수 기록
- 모든 엔딩 수집률

---

## 12. 설정 저장

게임 설정은 진행 데이터와 별도로 저장한다.

저장할 설정은 다음과 같다.

- 배경음악 음량
- 효과음 음량
- 음소거 여부
- 텍스트 출력 속도
- 화면 효과 사용 여부
- 진동 사용 여부
- 확인 창 표시 여부

새 게임을 시작해도 설정은 유지한다.

---

## 13. 저장하지 않아도 되는 정보

잠시 화면에만 표시되는 정보는 저장하지 않아도 된다.

예시:

- 버튼을 누르는 중인지 여부
- 현재 재생 중인 짧은 애니메이션
- 팝업의 일시적인 위치
- 마우스 또는 터치 상태
- 일시적인 로딩 표시
- 화면 전환 효과의 진행 정도

불러오기 후에는 저장된 데이터를 기준으로 화면을 다시 구성한다.

---

## 14. 저장 슬롯

### 초기 프로토타입

- 자동 저장 슬롯 1개
- 영구 기록 슬롯 1개
- 설정 저장 슬롯 1개

### 정식 버전 확장

- 자동 저장 슬롯 1개
- 수동 저장 슬롯 3개
- 영구 기록 슬롯 1개
- 설정 저장 슬롯 1개

각 수동 저장 슬롯에는 다음 정보를 표시한다.

- 선택한 연습생
- 현재 날짜
- 현재 순위
- 현재 팬 수
- 저장 날짜와 시간
- 대표 이미지

---

## 15. 브라우저 저장 방식

초기 웹 프로토타입에서는 브라우저의 `localStorage`를 사용할 수 있다.

### 저장 항목 예시

- `projectStar_save`
- `projectStar_records`
- `projectStar_settings`
- `projectStar_saveVersion`

`localStorage`는 같은 기기의 같은 브라우저에서만 유지된다.

브라우저 데이터를 삭제하거나 다른 기기를 사용하면 저장 데이터가 사라질 수 있다.

---

## 16. 저장 데이터 버전

게임 업데이트로 데이터 구조가 변경될 수 있으므로 저장 버전을 기록한다.

예시:

- 저장 버전 1: 기본 3일 프로토타입
- 저장 버전 2: 미션 시스템 추가
- 저장 버전 3: 아이템과 관계도 추가

게임을 실행할 때 저장 데이터의 버전을 확인한다.

이전 버전의 데이터를 읽을 수 있다면 새로운 형식으로 변환한다.

변환할 수 없는 경우에는 오류 안내를 표시한다.

---

## 17. 저장 오류 처리

저장 과정에서 문제가 발생해도 게임이 멈추지 않도록 한다.

### 저장 실패 안내

> 진행 상황을 저장하지 못했습니다.  
> 브라우저 저장 공간을 확인한 뒤 다시 시도해 주세요.

### 데이터 손상 안내

> 저장 데이터를 정상적으로 불러오지 못했습니다.  
> 새 게임을 시작하거나 저장 데이터를 초기화할 수 있습니다.

### 선택지

- 다시 불러오기
- 새 게임 시작
- 저장 데이터 초기화
- 타이틀로 돌아가기

저장 데이터를 자동으로 삭제하기 전에는 반드시 플레이어의 확인을 받는다.

---

## 18. 중복 보상 방지

불러오기를 반복해 같은 보상을 여러 번 얻지 못하도록 한다.

다음 항목에는 보상 지급 여부를 함께 기록한다.

- 이벤트 결과
- 미션 보상
- 하루 종료 보상
- 순위 달성 보상
- 엔딩 해금
- 도감 해금
- 아이템 획득

보상 적용과 저장은 가능한 한 같은 순서 안에서 처리한다.

---

## 19. 최종 엔딩 이후 저장

엔딩이 확정되면 다음 순서로 저장한다.

1. 최종 순위 확정
2. 엔딩 조건 판정
3. 영구 기록 업데이트
4. 엔딩 도감 해금
5. 최종 플레이 기록 저장
6. 진행 중인 자동 저장 종료 처리
7. 결과 화면 표시

엔딩 이후에는 완료된 플레이를 이어할 수 없다.

대신 같은 연습생으로 다시 시작하거나 다른 연습생을 선택할 수 있다.

---

## 20. 플레이 기록

완료된 플레이는 기록 메뉴에서 확인할 수 있다.

### 기록 항목

- 플레이 번호
- 선택한 연습생
- 최종 순위
- 최종 팬 수
- 최종 스타성
- 최종 능력치
- 획득한 엔딩
- 가장 많이 실행한 행동
- 확인한 이벤트 수
- 플레이 완료 날짜

초기 프로토타입에서는 최근 플레이 기록만 저장해도 된다.

정식 버전에서는 여러 개의 과거 기록을 보관한다.

---

## 21. 저장 데이터 초기화

설정 화면에서 저장 데이터를 초기화할 수 있다.

초기화 항목을 구분한다.

### 진행 데이터만 삭제

- 현재 진행 중인 플레이 삭제
- 도감과 기록은 유지

### 기록 데이터 삭제

- 엔딩 도감 삭제
- 이벤트 도감 삭제
- 최고 기록 삭제
- 현재 진행 데이터는 유지 가능

### 전체 데이터 삭제

- 현재 진행 데이터
- 모든 도감
- 모든 기록
- 설정

전체 삭제 전에는 두 번 확인한다.

### 확인 문구

> 모든 저장 데이터가 삭제됩니다.  
> 삭제한 데이터는 복구할 수 없습니다.

---

## 22. 클라우드 저장

클라우드 저장은 초기 프로토타입에서 구현하지 않는다.

정식 버전에서는 다음 기능을 고려할 수 있다.

- 계정 로그인
- 여러 기기 간 데이터 동기화
- 자동 백업
- 저장 데이터 복구
- 기기 변경 지원

로컬 저장 기능이 안정적으로 작동한 뒤 추가한다.

---

## 23. 저장 화면 연출

자동 저장 중에는 화면 한쪽에 짧은 표시를 출력한다.

### 표시 예시

- 저장 중…
- 저장 완료
- 자동 저장되었습니다.

저장 표시가 게임 진행을 가리거나 플레이를 멈추게 하지 않도록 한다.

---

## 24. 개발 우선순위

저장 시스템은 다음 순서로 구현한다.

1. 새 게임 데이터 생성
2. 자동 저장
3. 이어하기
4. 하루 종료 데이터 저장
5. 최종 기록 저장
6. 엔딩 도감 저장
7. 설정 저장
8. 데이터 초기화
9. 수동 저장 슬롯
10. 클라우드 저장

---

## 25. 제작 원칙

저장 시스템을 제작할 때는 다음 원칙을 지킨다.

- 플레이어가 저장 시점을 신경 쓰지 않아도 진행 상황이 보호되어야 한다.
- 보상이 중복 지급되지 않아야 한다.
- 새 게임을 시작해도 도감과 기록은 유지되어야 한다.
- 저장 데이터가 없을 때 이어하기 버튼을 표시하지 않는다.
- 데이터 삭제 전에는 반드시 확인을 받는다.
- 저장 오류가 발생해도 게임 전체가 멈추지 않아야 한다.
- 오래된 저장 데이터도 가능한 범위에서 불러올 수 있어야 한다.
- 저장 구조는 이후 시스템을 추가하기 쉽게 구성한다.
