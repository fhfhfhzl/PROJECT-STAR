# PROJECT STAR — UI / UX

## 1. UI·UX 개요

PROJECT STAR의 화면은 세로형 모바일 플레이를 기준으로 제작한다.

플레이어가 처음 게임을 실행하더라도 현재 상태와 다음 행동을 쉽게 이해할 수 있어야 한다.

화면은 화려한 아이돌 서바이벌 분위기를 유지하면서도 버튼과 정보가 복잡하게 겹치지 않도록 구성한다.

---

## 2. 기본 화면 방향

- 기본 화면 비율: 세로형
- 우선 지원 환경: 모바일 브라우저
- 보조 지원 환경: 태블릿과 PC 브라우저
- 한 손으로 주요 버튼을 누를 수 있도록 구성
- 중요한 버튼은 화면 아래쪽에 배치
- 가로 스크롤은 사용하지 않음

PC 화면에서도 게임 영역은 지나치게 넓어지지 않도록 중앙에 세로형으로 표시한다.

---

## 3. 디자인 분위기

PROJECT STAR는 다음 이미지를 중심으로 디자인한다.

- 글로벌 아이돌 오디션
- 화려한 무대 조명
- 방송 프로그램
- 연습생의 청춘과 성장
- 경쟁과 긴장감
- 팬들의 실시간 반응

기본 화면은 깔끔하고 밝게 구성하며, 중요한 평가와 결과 화면에서는 무대 조명과 방송 그래픽을 강조한다.

---

## 4. 기본 색상 방향

정확한 색상 코드는 개발 과정에서 조정할 수 있다.

### 기본 배경

- 흰색
- 밝은 회색
- 매우 옅은 푸른색

### 주요 강조색

- 남색
- 파란색
- 보라색 계열

### 특별 강조색

- 별과 스타성: 금색
- 성공과 순위 상승: 밝은 강조색
- 실패와 경고: 붉은색
- 체력 회복: 초록색

색상만으로 결과를 구분하지 않고 아이콘과 문구를 함께 표시한다.

---

## 5. 글꼴과 텍스트

텍스트는 모바일 화면에서도 쉽게 읽을 수 있어야 한다.

### 제목

- 화면 이름과 중요한 결과에 사용
- 굵고 크게 표시
- 한 화면에 큰 제목을 여러 개 사용하지 않음

### 본문

- 설명과 캐릭터 대사에 사용
- 너무 작은 글씨를 사용하지 않음
- 한 문단을 지나치게 길게 작성하지 않음

### 숫자

- 팬 수
- 순위
- 체력
- 능력치
- 남은 행동 횟수

중요한 숫자는 본문보다 크고 굵게 표시한다.

---

## 6. 공통 화면 구조

대부분의 게임 화면은 다음 순서로 구성한다.

1. 상단 정보 영역
2. 캐릭터 또는 대표 이미지
3. 현재 상황 설명
4. 주요 정보 카드
5. 선택 버튼
6. 하단 메뉴 또는 다음 버튼

한 화면 안에 지나치게 많은 정보를 넣지 않는다.

내용이 길면 세로 스크롤을 사용한다.

---

## 7. 상단 정보 영역

육성 화면 상단에는 현재 진행 상태를 표시한다.

### 표시 정보

- 현재 날짜
- 남은 행동 횟수
- 현재 순위
- 설정 버튼

표시 예시:

- DAY 1 / 3
- 남은 행동 4 / 6
- 현재 순위 3위

상단 정보는 화면을 스크롤해도 확인할 수 있도록 고정할 수 있다.

---

## 8. 타이틀 화면

타이틀 화면은 게임의 첫인상을 결정하는 화면이다.

### 표시 요소

- 다섯 연습생의 이미지
- PROJECT STAR 로고
- GAME START
- 도감
- 기록
- 설정
- 게임 방법

### 화면 구성

상단에는 PROJECT STAR 로고를 배치한다.

중앙에는 다섯 연습생의 이미지를 배치한다.

하단에는 메뉴 버튼을 세로로 정렬한다.

### 버튼 순서

1. GAME START
2. 도감
3. 기록
4. 설정
5. 게임 방법

GAME START 버튼은 다른 버튼보다 크게 표시한다.

---

## 9. 타이틀 화면 캐릭터 이미지

다섯 연습생은 기존에 확정된 외형을 유지한다.

- 강시우
- 한도윤
- 이서준
- 차민준
- 윤하준

캐릭터의 얼굴, 머리색, 헤어스타일과 기본 의상을 임의로 변경하지 않는다.

타이틀 화면에서는 한 명만 지나치게 크게 보이지 않도록 다섯 명의 비중을 균형 있게 맞춘다.

---

## 10. 게임 시작 버튼

GAME START를 누르면 저장 데이터 상태에 따라 화면이 달라진다.

### 저장 데이터가 없는 경우

연습생 선택 화면으로 이동한다.

### 진행 중인 저장 데이터가 있는 경우

다음 선택지를 표시한다.

- 이어하기
- 새 게임
- 취소

새 게임을 선택하면 기존 진행 데이터가 사라진다는 확인 창을 표시한다.

---

## 11. 연습생 선택 화면

다섯 연습생의 프로필 카드를 세로로 보여준다.

### 카드 표시 정보

- 프로필 이미지
- 이름
- 나이
- 포지션
- 성장 유형
- 대표 능력
- 예상 난이도

캐릭터 카드를 누르면 상세 프로필을 표시한다.

### 선택 버튼

각 프로필 아래에 `이 연습생 선택` 버튼을 배치한다.

선택 후에는 확인 창을 표시한다.

> 이 연습생의 담당자가 되어 PROJECT STAR를 시작하시겠습니까?

---

## 12. 캐릭터 상세 프로필

상세 프로필에는 다음 정보를 표시한다.

- 캐릭터 전신 또는 상반신 이미지
- 이름
- 나이
- 포지션
- 성격 요약
- 성장 유형
- 초기 능력치
- 캐릭터 소개
- 플레이 난이도

능력치는 막대 또는 별 형태로 표현할 수 있다.

숫자도 함께 표시해 정확한 정보를 확인할 수 있도록 한다.

---

## 13. 메인 육성 화면

메인 육성 화면은 플레이 중 가장 자주 보는 화면이다.

### 상단

- 현재 날짜
- 남은 행동 횟수
- 현재 순위
- 설정 버튼

### 중앙

- 선택한 연습생 이미지
- 현재 대사
- 체력
- 팬 수
- 스타성

### 하단

- 능력치 카드
- 행동 선택 버튼
- 미션 버튼
- 기록 또는 상태 확인 버튼

한 화면에 모든 행동 버튼이 들어가지 않으면 두 줄 또는 세로 목록으로 배치한다.

---

## 14. 연습생 상태 영역

선택한 연습생의 상태는 카드 형태로 표시한다.

### 표시 정보

- 이름
- 현재 체력
- 팬 수
- 스타성
- 현재 순위

### 체력

체력은 숫자와 게이지를 함께 표시한다.

예시:

`체력 72 / 100`

체력이 낮아질수록 경고 표시를 추가한다.

### 스타성

별 아이콘과 숫자를 함께 표시한다.

예시:

`스타성 ★★★☆☆`

### 팬 수

큰 숫자로 표시하고 증가 또는 감소량을 함께 보여준다.

예시:

`팬 1,240명`

`오늘 +180명`

---

## 15. 능력치 화면

다섯 가지 능력치를 한눈에 확인할 수 있도록 구성한다.

- 보컬
- 댄스
- 랩
- 예능
- 연기

각 능력치에는 다음 정보를 표시한다.

- 능력치 이름
- 현재 레벨
- 현재 경험치
- 다음 레벨까지 필요한 경험치
- 진행 게이지

표시 예시:

`보컬 Lv.3`

`경험치 24 / 40`

---

## 16. 행동 선택 화면

플레이어는 다음 행동을 선택할 수 있다.

- 보컬 연습
- 댄스 연습
- 랩 연습
- 예능 촬영
- 연기 연습
- SNS 활동
- 휴식

각 버튼에는 다음 정보를 함께 표시한다.

- 행동 이름
- 대표 아이콘
- 예상 체력 소비
- 주요 효과

예시:

`보컬 연습`

`보컬 경험치 증가 · 체력 -6`

---

## 17. 행동 버튼 상태

### 선택 가능

일반적인 버튼 모양으로 표시한다.

### 체력 부족

버튼을 흐리게 표시하고 누를 수 없게 한다.

버튼 아래에 이유를 표시한다.

> 체력이 부족합니다.

### 행동 횟수 부족

남은 행동이 0회라면 모든 행동 버튼을 비활성화한다.

자동으로 하루 종료 화면으로 이동한다.

### 특별 보너스 적용

캐릭터 특기나 아이템 효과가 적용될 경우 작은 표시를 추가한다.

예시:

- 특기 보너스
- 경험치 증가
- 이벤트 확률 상승

---

## 18. 행동 확인

일반 훈련은 빠른 진행을 위해 별도의 확인 창 없이 바로 실행할 수 있다.

다음 경우에는 확인 창을 표시한다.

- 마지막 행동
- 체력이 매우 낮은 상태
- 특별 아이템 사용
- 결과를 되돌릴 수 없는 선택

마지막 행동 확인 문구:

> 오늘의 마지막 행동입니다.  
> 이 행동을 진행하시겠습니까?

---

## 19. 행동 결과 팝업

행동이 끝나면 짧은 결과 팝업을 표시한다.

### 표시 정보

- 실행한 행동
- 획득한 경험치
- 감소하거나 회복한 체력
- 증가하거나 감소한 팬 수
- 레벨 상승 여부
- 캐릭터의 짧은 대사

예시:

> 댄스 연습을 완료했습니다.

- 댄스 경험치 +12
- 체력 -8
- 팬 +20

결과를 확인하면 메인 육성 화면으로 돌아간다.

---

## 20. 레벨 상승 연출

능력치 레벨이 상승하면 일반 행동 결과보다 눈에 띄게 표시한다.

### 표시 요소

- LEVEL UP
- 상승한 능력치
- 이전 레벨
- 새로운 레벨
- 짧은 빛 또는 별 효과

연출은 짧게 유지하며 건너뛰기 버튼을 제공할 수 있다.

---

## 21. STAR EVENT 화면

STAR EVENT가 발생하면 일반 화면과 다른 분위기를 사용한다.

### 표시 요소

- STAR EVENT 제목
- 이벤트 이미지 또는 캐릭터 표정
- 상황 설명
- 캐릭터 대사
- 선택지 두 개 이상

도전적인 선택과 안정적인 선택이 시각적으로 구분되도록 한다.

하지만 어느 선택이 정답인지 직접 표시하지 않는다.

---

## 22. 선택지 버튼

선택지에는 행동의 의미가 분명하게 드러나야 한다.

좋지 않은 예시:

- 선택 1
- 선택 2

좋은 예시:

- 직접 센터 자리에 선다
- 원래 위치에서 연습을 계속한다

선택지 문장은 짧고 이해하기 쉽게 작성한다.

---

## 23. 이벤트 결과 화면

선택 후에는 결과를 바로 보여준다.

### 성공

- 성공 문구
- 팬 수 변화
- 스타성 변화
- 능력치 변화
- 캐릭터 대사

### 실패

- 실패 상황
- 감소한 팬 수 또는 체력
- 캐릭터의 반응
- 다음 플레이로 이어지는 문구

실패를 지나치게 부정적으로 표현하지 않는다.

---

## 24. PROJECT STAR NOW 화면

하루 종료 후 팬 반응을 보여주는 SNS 형식의 화면이다.

### 표시 요소

- PROJECT STAR NOW 로고
- 선택한 연습생의 이름과 사진
- 오늘의 팬 변화
- 현재 순위
- 팬 게시글
- 댓글 또는 반응

팬 반응 카드는 실제 SNS처럼 보이되 특정 실제 서비스의 디자인을 그대로 복제하지 않는다.

---

## 25. 팬 반응 카드

각 팬 반응에는 다음 요소를 사용할 수 있다.

- 임의의 팬 닉네임
- 프로필 아이콘
- 반응 문장
- 좋아요 수
- 게시 시간

팬 닉네임은 실존 인물과 관계없는 가상의 이름으로 제작한다.

같은 문장이 지나치게 반복되지 않도록 여러 반응을 준비한다.

---

## 26. DAILY RESULT 화면

팬 반응 확인 후 하루의 전체 결과를 보여준다.

### 표시 정보

- 날짜
- 현재 순위
- 전날 대비 순위 변화
- 오늘 증가한 팬 수
- 현재 전체 팬 수
- 성장한 능력치
- 현재 스타성
- 남은 체력
- 다른 참가자들의 순위

### 버튼

- 다음 날로
- 능력치 상세 보기
- 참가자 순위 보기

3일 차에는 `최종 결과 확인` 버튼으로 변경한다.

---

## 27. 순위 화면

다섯 연습생의 현재 순위를 세로 목록으로 표시한다.

### 각 순위 항목

- 순위
- 프로필 이미지
- 이름
- 팬 수
- 스타성
- 대표 능력치
- 순위 변화

플레이어가 선택한 연습생의 항목은 테두리나 아이콘으로 강조한다.

순위 상승과 하락은 화살표와 숫자를 함께 표시한다.

---

## 28. 최종 순위 발표 화면

최종 순위는 5위부터 1위까지 차례대로 공개한다.

### 연출

- 무대 배경
- 긴장감을 주는 짧은 전환
- 순위 숫자 표시
- 연습생 이미지
- 최종 팬 수와 대표 능력

선택한 연습생의 순위가 발표될 때는 별도의 대사와 강조 연출을 사용한다.

연출을 빠르게 넘길 수 있는 버튼을 제공할 수 있다.

---

## 29. 엔딩 화면

엔딩 화면은 플레이 결과를 정리하고 성취감을 주는 화면이다.

### 표시 요소

- 엔딩 이름
- 캐릭터 이미지
- 엔딩 설명
- 마지막 대사
- 최종 순위
- 최종 팬 수
- 최종 스타성
- 가장 높은 능력치

### 버튼

- 기록 저장
- 엔딩 도감 보기
- 같은 연습생으로 다시 시작
- 다른 연습생 선택
- 타이틀로 돌아가기

가장 중요한 버튼 한 개를 크게 표시하고 나머지는 보조 버튼으로 배치한다.

---

## 30. 도감 화면

도감에서는 수집한 내용을 확인할 수 있다.

### 도감 분류

- 캐릭터
- 이벤트
- 엔딩
- 기록
- 이미지

해금하지 못한 항목은 실루엣 또는 잠금 아이콘으로 표시한다.

필요한 경우 일부 해금 조건을 힌트로 보여준다.

---

## 31. 기록 화면

기록 화면에는 이전 플레이 결과를 표시한다.

### 표시 정보

- 선택한 연습생
- 최종 순위
- 최종 팬 수
- 최종 스타성
- 대표 능력치
- 획득한 엔딩
- 완료 날짜

최근 기록을 먼저 보여준다.

기록이 없을 경우 빈 화면만 보여주지 않고 안내 문구를 표시한다.

> 아직 완료한 플레이가 없습니다.

---

## 32. 설정 화면

설정 화면에는 다음 항목을 제공한다.

- 배경음악 음량
- 효과음 음량
- 음소거
- 텍스트 속도
- 화면 효과
- 진동
- 저장 데이터 관리

설정 변경은 즉시 저장한다.

저장 데이터 삭제 버튼은 다른 버튼과 떨어진 위치에 배치한다.

---

## 33. 게임 방법 화면

게임 방법은 초보자도 이해할 수 있도록 짧은 항목으로 나눈다.

### 설명 항목

- 게임 목표
- 하루 행동 횟수
- 능력치
- 체력
- 팬 수
- 스타성
- 순위
- 엔딩

긴 설명을 한 페이지에 모두 넣지 않고 여러 카드 또는 접을 수 있는 항목으로 구성한다.

---

## 34. 팝업 창

팝업은 중요한 확인이나 짧은 결과에만 사용한다.

### 팝업 사용 상황

- 캐릭터 선택 확인
- 새 게임 확인
- 저장 데이터 삭제
- 체력 부족 경고
- 행동 결과
- 아이템 사용
- 게임 종료 확인

팝업 바깥을 눌렀을 때 닫혀도 되는지 상황에 따라 구분한다.

삭제와 새 게임 확인 창은 바깥을 눌러도 닫히지 않도록 할 수 있다.

---

## 35. 버튼 디자인

버튼은 누를 수 있는 영역이 분명해야 한다.

### 기본 원칙

- 버튼 사이에 충분한 간격을 둔다.
- 너무 작은 버튼을 사용하지 않는다.
- 누른 상태가 시각적으로 보여야 한다.
- 비활성화 상태를 분명하게 표시한다.
- 같은 기능에는 같은 형태의 버튼을 사용한다.

### 버튼 종류

- 주요 버튼
- 보조 버튼
- 뒤로 가기 버튼
- 위험 동작 버튼
- 잠긴 버튼

삭제와 초기화처럼 위험한 기능은 일반 버튼과 다르게 표시한다.

---

## 36. 뒤로 가기

화면 왼쪽 위에는 필요한 경우 뒤로 가기 버튼을 배치한다.

게임 진행 중 이전 화면으로 돌아가 결과를 취소할 수는 없다.

다음 상황에서는 뒤로 가기 전에 확인한다.

- 진행 중인 이벤트
- 캐릭터 선택 완료 후
- 최종 결과 진행 중
- 저장되지 않은 설정 변경

---

## 37. 로딩 화면

이미지와 데이터를 준비하는 동안 로딩 화면을 표시한다.

### 표시 요소

- PROJECT STAR 로고
- 별 모양 로딩 표시
- 짧은 안내 문구

예시:

- 무대를 준비하고 있습니다.
- 연습생들의 결과를 계산하고 있습니다.
- 팬들의 반응을 불러오고 있습니다.

로딩 시간이 짧다면 전체 화면을 가리지 않고 작은 표시만 사용할 수 있다.

---

## 38. 오류 화면

오류가 발생하면 원인을 알 수 없는 코드만 보여주지 않는다.

### 기본 오류 문구

> 문제가 발생했습니다.  
> 다시 시도해 주세요.

### 버튼

- 다시 시도
- 타이틀로 돌아가기

저장 오류일 경우 현재 데이터가 사라질 수 있는지 명확하게 알려준다.

---

## 39. 화면 전환

화면 전환은 짧고 자연스럽게 구성한다.

### 사용할 수 있는 효과

- 페이드
- 위아래 이동
- 카드 등장
- 별빛 효과
- 무대 조명 효과

모든 화면에 화려한 효과를 사용하지 않는다.

평가, STAR EVENT와 엔딩처럼 중요한 장면에서만 특별한 연출을 사용한다.

---

## 40. 캐릭터 대사

캐릭터 대사는 이미지 아래 또는 말풍선 형태로 표시한다.

### 표시 요소

- 캐릭터 이름
- 대사
- 표정 이미지
- 다음 버튼

대사가 길면 여러 화면으로 나눈다.

한 번에 지나치게 많은 문장을 표시하지 않는다.

---

## 41. 이미지 사용 원칙

확정된 캐릭터 이미지의 외형을 임의로 변경하지 않는다.

특히 다음 요소를 유지한다.

- 얼굴
- 머리색
- 헤어스타일
- 눈 모양
- 체형
- 기본 오디션 의상
- 캐릭터별 넥타이와 액세서리

배경 제거와 크기 조정은 가능하지만 인물 자체의 외형은 변경하지 않는다.

이미지가 늘어나더라도 파일 이름을 일관성 있게 관리한다.

---

## 42. 이미지 표시 방식

캐릭터 이미지는 용도에 따라 구분한다.

### 프로필 이미지

- 정사각형 또는 원형
- 연습생 선택 화면
- 순위 화면
- 팬 반응 화면

### 상반신 이미지

- 대화 화면
- 행동 결과
- 이벤트 화면

### 전신 이미지

- 캐릭터 상세 프로필
- 타이틀 화면
- 엔딩 화면

같은 캐릭터의 이미지 비율이 화면마다 지나치게 달라 보이지 않도록 한다.

---

## 43. 모바일 터치 사용성

모바일 환경에서는 마우스를 올렸을 때만 나타나는 기능을 사용하지 않는다.

모든 주요 기능은 터치만으로 사용할 수 있어야 한다.

버튼은 손가락으로 누르기 충분한 크기로 제작한다.

화면 아래쪽의 버튼이 브라우저 메뉴나 기기 영역에 가려지지 않도록 여백을 둔다.

---

## 44. 접근성

가능한 범위에서 다음 접근성 기준을 적용한다.

- 글자와 배경의 명도 차이를 충분히 확보
- 색상 외에도 아이콘과 글자로 상태 표시
- 작은 글씨 사용 제한
- 애니메이션 감소 설정 제공
- 음소거 상태에서도 결과 이해 가능
- 이미지에 대체 설명 추가
- 버튼의 기능을 명확한 문장으로 표시

---

## 45. 텍스트 표현 원칙

버튼과 안내 문구는 짧고 직접적으로 작성한다.

좋은 예시:

- 보컬 연습
- 다음 날로
- 결과 확인
- 다시 시도
- 타이틀로 돌아가기

좋지 않은 예시:

- 이것을 선택하여 다음 과정으로 진행하기
- 해당 활동을 실시합니다

게임 용어는 모든 화면에서 같은 표현을 사용한다.

예를 들어 `팬`, `팬 수`, `팔로워`를 섞어 쓰지 않고 기본적으로 `팬 수`로 통일한다.

---

## 46. 알림 메시지

짧은 상태 변화는 화면 위쪽 또는 아래쪽에 작은 알림으로 표시한다.

### 예시

- 자동 저장되었습니다.
- 팬 수가 120명 증가했습니다.
- 댄스 레벨이 상승했습니다.
- 새로운 이벤트가 기록되었습니다.
- 엔딩 도감이 해금되었습니다.

알림은 자동으로 사라지며 게임 진행을 막지 않는다.

---

## 47. 초보자 안내

첫 플레이에서는 필요한 순간에만 간단한 설명을 표시한다.

### 안내 시점

- 첫 번째 행동 선택
- 체력 최초 감소
- STAR EVENT 최초 발생
- 하루 종료
- 첫 순위 발표
- 최종 엔딩

이미 확인한 안내는 다시 표시하지 않도록 저장할 수 있다.

모든 설명을 게임 시작 전에 한꺼번에 보여주지 않는다.

---

## 48. 화면별 우선순위

### 1차 구현

- 타이틀 화면
- 연습생 선택 화면
- 캐릭터 소개 화면
- 메인 육성 화면
- 행동 결과 팝업
- STAR EVENT 화면
- PROJECT STAR NOW 화면
- DAILY RESULT 화면
- 최종 순위 화면
- 엔딩 화면

### 2차 구현

- 이어하기
- 게임 방법
- 설정
- 저장 데이터 관리
- 기록

### 3차 구현

- 도감
- 미션 화면
- 아이템 화면
- 관계도 화면
- 상세 캐릭터 스토리

---

## 49. 현재 프로토타입 적용 범위

초기 프로토타입에서는 기능을 확인할 수 있는 단순한 화면부터 제작한다.

우선 필요한 요소는 다음과 같다.

- 세로형 모바일 화면
- 텍스트와 버튼 중심의 진행
- 선택한 연습생 이미지 표시
- 능력치와 체력 표시
- 행동 버튼
- 팬 반응
- 순위
- 기본 엔딩

화려한 애니메이션과 복잡한 화면 효과는 기본 게임이 정상적으로 작동한 뒤 추가한다.

---

## 50. 제작 원칙

UI와 UX를 제작할 때는 다음 원칙을 지킨다.

- 플레이어가 다음에 눌러야 할 버튼을 쉽게 찾을 수 있어야 한다.
- 한 화면에 지나치게 많은 정보를 표시하지 않는다.
- 중요한 숫자와 상태를 명확하게 보여준다.
- 모바일 세로 화면을 우선한다.
- 캐릭터 이미지를 임의로 변경하지 않는다.
- 같은 기능은 모든 화면에서 같은 형태로 표현한다.
- 실패와 오류 상황에서도 다음 행동을 안내한다.
- 화려함보다 게임을 이해하기 쉬운 구조를 먼저 완성한다.
